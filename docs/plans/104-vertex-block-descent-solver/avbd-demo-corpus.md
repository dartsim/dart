# AVBD Demo And Benchmark Corpus Matrix

This matrix is the detailed inventory of PLAN-104's narrow AVBD scene and
benchmark surfaces. The authoritative cross-family completion rule and
canonical row inventory are
[`paper-parity-matrix.md`](paper-parity-matrix.md) and
[`avbd-paper-coverage-contract.json`](avbd-paper-coverage-contract.json).
The active implementation tracker remains
[`../../dev_tasks/avbd_solver/`](../../dev_tasks/avbd_solver/), and the method
scope remains
[`avbd-paper-gap-audit.md`](avbd-paper-gap-audit.md). This file records the
existing source-demo, paper, website/video, and performance artifacts without
promoting narrow packet status into a paper-parity claim.

## Evidence Contract

Do not mark any row complete until DART owns all required evidence:

- a correctness invariant in a test or benchmark;
- a runnable `py-demos` scene or another durable visual/smoke surface when
  visual behavior matters;
- benchmark JSON or dashboard data for performance rows;
- CPU and GPU coverage when the source or paper claim includes both; and
- explicit comparison against the reference demo or paper number when making a
  speed or parity claim.

Status values:

- `Missing`: no DART-owned scene/test/benchmark exists.
- `Partial`: DART has a narrow foundation or related showcase, but it is not a
  source-demo or paper-scene reproduction.
- `Ready for implementation`: enough solver foundation exists to port the row
  next without first creating another internal row family.
- `Blocked by foundation`: required row families, coupling, GPU path, or
  candidate generation are still missing.
- `Complete`: the current DART surface has runtime-resolved solver identity and
  meets this matrix's local evidence contract. A legacy packet without that
  identity can be useful historical fixture evidence, but cannot be `Complete`
  and cannot close an AVBD correctness, parity, or performance claim. Only the
  machine-checked coverage contract can close the corresponding canonical row.

## Runtime Solver-Identity Audit

A zero-trust source audit supersedes the earlier name-based relabel. The
`avbd_demo*` filenames and `BM_Avbd*` benchmark symbols remain labels rather
than execution evidence, so the current source makes identity explicit:

- All 31 current `avbd_demo2d_*` and `avbd_demo3d_*` Python scenes select the
  public AVBD rigid-body family. Their checked-in historical captures and
  timings still require current-source regeneration before supporting AVBD
  claims.
- The free-rigid and 2D/3D source fixtures in
  `tests/benchmark/simulation/bm_avbd_rigid_fixed_joint.cpp` select public
  AVBD, and every stepping row checks and records its resolved runtime family.
  API-only and empty-world rows record that solver identity is not applicable.
- In particular, the articulated and high-ratio chain fixtures explicitly
  select `MultibodyIntegrationFamily::Variational`. Their historically named
  `BM_Avbd*` rows and packets are Variational evidence, not AVBD evidence.

The checked-in source-demo packets predate current runtime selection and remain
historical whole-pipeline `World::step` or fixture-topology comparisons. Their
numeric ratios may describe the captured program, but they cannot establish an
AVBD speedup, regression, paper-parity result, or completed AVBD corpus row.
Changing current scenes and benchmarks to select AVBD does not retroactively
change those packets. Every refreshed claim must machine-record runtime-resolved
configuration, including `resolved_solver_identity` and
`rigid_contact_selection`, at current AVBD packet schema version 6. Paper
benchmark rows additionally bind the resolved solver-configuration fingerprint
and the numeric AVBD parameter profile. The
`pixi run check-avbd-packets` gate must reject a filename-, symbol-, or
requested-configuration inference when the executed solver identity is absent.

The separate `avbd_paper_breakable_wall` surface selects the public AVBD
family, the matched `vbd_paper_breakable_wall` surface selects the public
fixed-penalty VBD family, and `sequential_impulse_paper_breakable_wall`
selects the public Sequential Impulse family. All three record solver identity
and share one reconstructed scene fingerprint. They are paper-shaped
comparison rows, not a retroactive solver-identity change to the source-demo
rows.

## Current Narrow DART Surfaces

These surfaces are useful foundations, but they do not complete the overall
paper/source-demo corpus. For every historically named `avbd_demo*` or
`BM_Avbd*` entry below, the coverage text describes topology or a captured
artifact only; it does not by itself identify the runtime solver. Current
free-rigid/source-scene builders select and report public AVBD, while
articulated/high-ratio builders remain explicitly Variational and API-only or
empty-world rows remain non-solver evidence. The predecessor packets do not
retroactively inherit those current identities.

The shared solver foundation now has step-start Taylor-linearized rigid contact,
persistent validated rigid/deformable friction anchors, live normal-force cone
refresh, inactive-dual cleanup, fail-closed fixed-penalty continuation, and
replay/capacity regressions. None of those focused mechanisms supplies a
source-demo trajectory, current long-horizon video, CUDA result, or comparable
performance packet, so every corpus row below remains `Partial` or otherwise
incomplete under its recorded blockers.

## Next Corpus Steps

1. Keep every intended AVBD demo and benchmark on explicit, fail-closed runtime
   selection; never infer selection from an `avbd_` filename or `BM_Avbd`
   symbol.
2. Re-run the complete 2D/3D source corpus with runtime-resolved identity in
   every current-schema packet. Historical pre-repair captures remain AVBD
   gaps, and the Variational multibody benchmarks remain deliberately
   reclassified rather than AVBD evidence.
3. Preserve the Variational high-ratio fixtures as reusable topology and
   stability scaffolding, but implement an actual public AVBD articulated path
   before using those fixtures for AVBD correctness, parameter, or performance
   evidence.
4. Re-establish CPU comparisons only after the executed AVBD scene matches the
   reference scene, timestep, iteration budget, compiler mode, and correctness
   target. Historical faster/slower ratios are not AVBD baselines.
5. Keep GPU and paper-number rows `Missing` until CUDA row parity and
   same-hardware, runtime-resolved benchmark packets exist.
